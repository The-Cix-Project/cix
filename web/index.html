State storage placement

				
State storage: unknown

				

				

					
					
				

				
Where thinC's own state lives (ADR-0141) -- networks, DNS/LDAP/NTP/syslog
					config, PKI, container definitions, site identity, daemon config. Never container
					workload data, never rebuildable content (images/packages), never logs. The target disk
					must already carry the state-storage role and be currently mounted. Live, no downtime --
					the daemon keeps operating against the current location until the copy finishes.


				
Log storage placement

PKI: Root CA

			
A browser or OS that doesn't already trust this install's own root CA will refuse HTTPS to this dashboard (and to any other thinc endpoint) with a certificate warning -- expected, since it's a private, self-signed CA, not a publicly trusted one. Download the certificate below and trust it once on whatever device you connect from; see "Trusting the CA on your own device" in docs/guides/security.md for the full, platform-by-platform steps (Windows/macOS/Linux/Firefox all differ). Short version: import the downloaded .crt into your OS or browser's own trusted-root store, marked to trust it for identifying websites.

			

			

				
				
				
			


			
PKI: Reset CA chain

			

				Wipes and regenerates the root (and intermediate, if bootstrapped),
				reissuing every currently-tracked leaf cert under the new chain.
				Destructive -- every previously-issued cert stops
				verifying against the new root the moment this completes. Leaves
				empty to default each name to thinC Root/Intermediate CA -
				<domain_suffix>.
			

			

				
				
				
			

			

		


		
		

			
PKI: Intermediate CA

			

				Optional second CA tier -- once bootstrapped, every future certificate
				issuance is signed by it instead of the root, and delivered certs carry
				the full chain. Requires the root CA (see Root CA) to already exist.

Host Swap

			
Swap: unknown

			

				
				
				
			

			
A single on-demand swap file (ADR-0069), off by default -- useful for memory-heavy package builds (e.g. Rust/wasm) on a box with limited RAM. File-backed swap performs identically to a partition on SSD/NVMe-backed storage.

		


		

			
Rolling Restart

			

				
				
			

			
Part 5, ADR-0124: when a rolling image auto-rebuilds, every follow_rolling container on it gets a uniformly-random restart delay up to this window, spreading the restarts out instead of killing them all in the same instant. 0 disables jitter (restart immediately).

TLS Throttle

				
Per-source-IP throttling for repeated failed HTTPS handshakes (ADR-0134) -- a source that fails enough handshakes within the window is refused outright, on both listeners, until the block expires. Loopback (127.0.0.1) is never throttled, so this daemon's own local admin access can't be locked out by a hostile source sharing the box.

Log Store

				
A consolidated log (ADR-0070/ADR-0126): real kernel dmesg, thincd's own diagnostics, a per-request audit trail, and every container's own stdout/stderr -- all in one place, size-capped with the oldest entries dropped first once the cap is reached. Browse it live in the Log panel at the bottom of every page (source filter includes this browser's own local activity too, kept client-side only) -- this page just configures the store's size cap, not what's logged.

				
Size cap

				

					
					
				

				
Enforced at segment granularity (8 rotating segments, oldest dropped whole when a new one is needed), not byte-exact -- a few percent of slop against this cap is expected.

			

		


		

			
Backup

				state + recipes, site config) -- not workload data, not image content, never PKI keys.
