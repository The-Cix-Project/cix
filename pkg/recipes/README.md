# pkg/recipes/

77 packages, each a `<name>/<version>/build.sh` — real, from-source build recipes for Kanxeo's own `pkg install`. Each `build.sh` is a plain shell script following a strict, documented format: see [`docs/guides/writing-recipes.md`](../../docs/guides/writing-recipes.md) for the complete authoring guide, with a real worked example.

Layout (ADR-0107, filename per ADR-0120): `<pkg_name>/<pkg_version>/build.sh`, where both the directory names and the recipe's own internal `pkg_name=`/`pkg_version=` fields must agree exactly. A package can have more than one published version side by side (e.g. `curl/8.20.0/build.sh` and `curl/8.21.0/build.sh`) — recipe versions are immutable once published, never overwritten in place; fixing a mistake means publishing a new version. Uploaded to a running daemon via `POST /pkg/recipes` or `kanxeoctl pkg recipe add --name=NAME --file=PATH` — these files are the *source* for a fresh deployment's initial catalog, never read directly off disk by `kanxeod` itself or baked into the installer ISO (see ADR-0040), and — since ADR-0120 — also fetchable in bulk via `pkg sync` from a configured git repo instead of one-at-a-time uploads.
