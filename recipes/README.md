# recipes/

Git-tracked source for Kanxeo's `pkg install`/`image apply-recipe` catalogs, split by kind (ADR-0149) — not by topic, not by the phase that introduced a given recipe:

- **[`package/`](package/)** — 77 packages, each `<name>/<version>/build.sh`: real, from-source build recipes. Layout unchanged from ADR-0107 (filename per ADR-0120): `<pkg_name>/<pkg_version>/build.sh`, where both the directory names and the recipe's own internal `pkg_name=`/`pkg_version=` fields must agree exactly. A package can have more than one published version side by side (e.g. `curl/8.20.0/build.sh` and `curl/8.21.0/build.sh`) — recipe versions are immutable once published, never overwritten in place; fixing a mistake means publishing a new version. See [`docs/guides/writing-recipes.md`](../docs/guides/writing-recipes.md) for the complete authoring guide, with a real worked example.
- **[`image/`](image/)** — declarative per-image package-list manifests, `<name>/<version>/build.sh` (ADR-0123's format, ADR-0149's layout): each `build.sh` is `image_packages="pkgname:mode:version ..."` plus an optional `image_artifact_sha256=`, not a shell script with `pkg_build()`/`pkg_install()` functions — the filename matches the package side purely for a uniform, predictable git layout, not because it executes as one. **The version directory here tracks the *recipe's own* revision history** (this declared package list changed, so it's a new version) — it is a completely separate concept from an image's actual build result, which is already content-addressed independently (ADR-0108). The daemon's own `image_recipe_add()` API stores exactly one current manifest per image name with no version parameter at all (ADR-0123's deliberate, unchanged design); `pkg sync` resolves which git version to publish by picking the highest per image name, the same "highest wins" rule an unpinned `pkg install NAME` already uses for package recipes.

Both kinds are uploaded to a running daemon via `POST /pkg/recipes` / `POST /images/recipes` (or `kanxeoctl pkg recipe add`/`image recipe add --file=PATH`) — these files are the *source* for a fresh deployment's initial catalog, never read directly off disk by `kanxeod` itself or baked into the installer ISO (see ADR-0040) — and, since ADR-0121 (package) and ADR-0149 (image), both fetchable in bulk via `pkg sync` from a configured git repo instead of one-at-a-time uploads.
