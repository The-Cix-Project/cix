# 0044 — `kanxeod --data-dir=` for test/production state isolation

## Status

Accepted

## Context

`daemon/src/main.c` hardcoded every piece of its own persistent state — image/container rootfs directories, `networks.json`, `dns_records.json`, the PKI directory, the pkg directory, `container_defs.json` — under a single compile-time `BASE_DIR "/var/lib/kanxeo"` macro. Every daemon-linked test (`test_daemon.c`, `test_pki.c`, `test_pkg.c`, and 13 others) spawns its own real `kanxeod` subprocess to drive over real HTTP, and every one of those subprocesses landed on that exact same default path — identical to whatever a real, already-running production `kanxeod` on the same host was using.

This stopped being theoretical mid-session: running this project's own test suite against this dev sandbox's own live daemon (serving a real 5-container VRRP/OSPF demo topology — `keeper`, `cr-1`, `cr-2`, `srv1`, `blah`) silently wiped that daemon's `container_defs.json`, `networks.json`, `dns_records.json`, regenerated its PKI CA, and — the most severe instance — wiped the `router` image's entire installed-package rootfs content and the daemon's own live recipe files, because every test's own `reset_state()` unconditionally `rm -rf`s these exact same shared paths. Stopping the live daemon first does not help — it does not prevent a subsequently-started test daemon from writing to the same shared path, and additionally kills every live container immediately via `PR_SET_PDEATHSIG`. This happened twice in the same session, both times requiring a full manual recovery (recreating networks/containers from captured state, reinstalling all `router` image packages from source).

A test-only path override was the fix under consideration; the alternative — namespacing every test by port alone while still sharing `/var/lib/kanxeo` — does nothing, since the collision is on disk paths, not TCP ports (tests already use distinct ports and still collided).

## Decision

**`kanxeod` gains a `--data-dir=PATH` startup flag**, defaulting to the unchanged `DEFAULT_BASE_DIR` (`/var/lib/kanxeo`) when omitted — zero behavior change for every existing production/installer/QEMU-boot code path that doesn't pass it. Every subsystem already receives its own state path as an explicit init-time parameter (`network_init(NETWORKS_STATE_PATH)`, `pkg_init(...)`, `image_init(IMAGES_DIR)`, etc. — confirmed by inspection before starting this change) — no subsystem has a second, internal hardcoded copy of its path. This meant the fix is fully contained to `daemon/src/main.c`: the compile-time `BASE_DIR`/derived-macro block became a runtime-mutable `g_base_dir[PATH_MAX]` (default `DEFAULT_BASE_DIR`) plus a set of derived `static char [PATH_MAX]` path buffers, computed once by a new `init_base_dir_paths()` called immediately after argv parsing (so `--data-dir=` has already been applied) and before `boot_init()` (which mounts the real containers partition at `g_base_dir` under `--init-mode`) or any subsystem `_init()` call touches any of them.

Two derived paths (`PKG_RECIPES_DIR`, `PKI_CERTS_DIR`) were added to the same computed-once set specifically because TCC (like standard C) cannot concatenate a runtime `char[]` with an adjacent string literal the way `PKG_DIR "/recipes"` worked as a compile-time macro — every call site that previously relied on that concatenation trick now references the correct pre-computed derived path instead, rather than each site growing its own local `snprintf`.

**Every daemon-linked test now creates its own throwaway `--data-dir=`, never the default.** A new shared helper (`test_data_dir_create()`/`test_data_dir_cleanup()`, `test/test_image_fixture.c` — the same file this codebase already centralizes test-fixture scaffolding in) wraps `mkdtemp("/tmp/kanxeo_test_data_XXXXXX")`, matching the exact naming convention `test_pki.c`/`test_installer.c`/`test_boot_ab.c` already each hand-rolled independently for their own scratch directories. All 16 daemon-linked tests were updated to call it before spawning their own `kanxeod` (passing `--data-dir=<created path>` in `dargv[]`) and to derive every path they themselves touch directly (fixture image roots, direct state-file reads/splices for persistence checks, `reset_state()`'s own `rm -rf` targets) from that same directory rather than a hardcoded `/var/lib/kanxeo/...` literal — the same class of hidden coupling that caused the original incident, just one level removed (a test reading/writing the real default path directly, bypassing the API, would have silently reintroduced the exact hazard this ADR exists to close).

One genuine, pre-existing test bug this isolation work surfaced rather than introduced: `test_images.c`'s "`base` is protected from deletion" check had never actually created a `base` image itself — it silently depended on a `base` image already existing from whatever prior state happened to be on disk (true by accident under the old shared-`/var/lib/kanxeo` setup, never true under a genuinely fresh isolated directory). Fixed by having the test create `base` via the real API first.

## Consequences

- Verified end-to-end: full clean rebuild (`make clean && make`), zero warnings; all 16 daemon-linked tests plus all 7 runtime-library tests pass under isolation; the live daemon's own real state (5 containers, `lan1`/`wan1` networks) confirmed byte-for-byte unaffected by the full test run, via direct `curl` before and after.
- `--data-dir=` is additive and backward-compatible — no existing invocation (installer, QEMU boot tests, a real operator's `kanxeod`) changes behavior, since the default is unchanged and every one of them already omits the flag.
- This closes the specific hazard that caused two real incidents this session, but does not make the test suite generally safe to run concurrently with itself — two test *processes* still can't share one `--data-dir=` (not attempted; each test invocation still gets its own fresh directory per run, sequentially, matching how this suite has always been run).
- Any new daemon-linked test written from here on must follow this same pattern (`test_data_dir_create()` + `--data-dir=` + deriving every direct-filesystem-touching path from it) — a bare `dargv[] = {"build/kanxeod", "--port=...", NULL}` reintroduces exactly the hazard this ADR closes.
